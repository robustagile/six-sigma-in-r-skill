# Method selection — by DMAIC phase

Use when the user frames the request in DMAIC terms ("we're in the Measure
phase", "for the Analyze step of this project", "we're done improving, time
to Control the process").

DMAIC is the standard Six Sigma project structure: **D**efine → **M**easure →
**A**nalyze → **I**mprove → **C**ontrol. Different phases pull in different
tools. The other two entry points —
[by problem type](method_by_problem.md) and
[by data shape](method_by_data_shape.md) — land in the same reference files
from a different starting question.

## Define

Mostly non-code deliverables: project charter, SIPOC, voice-of-customer
matrix, CTQ tree, stakeholder map. This skill doesn't generate those.

Code-relevant work: descriptive baselines on existing data to support the
problem statement.

- Baseline summary statistics → `descriptive_stats.md`
- Quick exploratory plots (run chart, histogram, box plot) →
  `charts_visualization.md`

## Measure

Quantify current performance before changing anything. Prove the measurement
system is trustworthy first.

| Task                                           | Reference                          |
| ---------------------------------------------- | ---------------------------------- |
| Baseline Cp/Cpk/Pp/Ppk                         | `capability_sigma_level.md`        |
| DPMO and current sigma level                   | `capability_sigma_level.md`        |
| Stability check before capability (run chart)  | `charts_visualization.md`          |
| Distribution shape / normality                 | `descriptive_stats.md`, `capability_sigma_level.md` |
| Subgroup vs individual data collection         | `control_charts.md` (decision tree at top) |

**MSA / Gage R&R is part of Measure** — but it isn't covered by this skill.
If the user asks about it, recommend the `SixSigma` CRAN package
(`ss.rr(...)`) or a custom `aov()`-based implementation; both are outside
the scope of the code templates here.

## Analyze

Find the root cause. This is where most of the statistical machinery lives.

| Question                                                | Technique                              | Reference                        |
| ------------------------------------------------------- | -------------------------------------- | -------------------------------- |
| Which few causes account for most of the problem?       | Pareto chart                           | `charts_visualization.md`        |
| Does X relate to Y?                                     | Correlation, then regression           | `correlation_regression.md`      |
| Is A really different from B?                           | 1- / 2-sample t, proportion, Wilcoxon  | `hypothesis_tests.md`            |
| Do three or more groups differ?                         | One-way ANOVA (parametric) or Kruskal-Wallis | `anova.md`                 |
| Two factors at once, possible interaction?              | Two-way ANOVA                          | `anova.md`                       |
| Does the observed frequency match expected?             | Chi-square goodness-of-fit             | `hypothesis_tests.md`            |
| Are two categorical variables associated?               | Chi-square independence                | `hypothesis_tests.md`            |
| Probability of k events / defectives given a rate?      | Binomial / Poisson calc                | `distributions.md`               |

Non-code Analyze tools (fishbone/Ishikawa, 5 Whys, SIPOC, value-stream map,
FMEA) aren't generated by this skill — direct the user to a diagram tool or
spreadsheet template.

## Improve

Design, test, and verify the fix.

| Task                                                   | Reference                          |
| ------------------------------------------------------ | ---------------------------------- |
| How many samples to detect the expected improvement?   | `sample_size_power.md`             |
| Before/after on the same units                         | Paired t / paired Wilcoxon (`hypothesis_tests.md`) |
| Before/after with different units                      | 2-sample t / Mann-Whitney (`hypothesis_tests.md`) |
| Re-score capability after the change                   | `capability_sigma_level.md`        |
| Verify multiple configurations (>2)                    | One-way ANOVA (`anova.md`)         |

**DOE (Design of Experiments) — factorial, fractional factorial, response
surface — is not covered by this skill.** If the user asks for DOE, point
them at the `FrF2`, `AlgDesign`, or `rsm` CRAN packages and offer to help
with post-hoc analysis (ANOVA on the factorial design output).

## Control

Keep the gain. Monitor the improved process so it doesn't drift back.

| Data type                                  | Chart                    | Reference              |

| Continuous, rational subgroups (2–10)      | X-bar R                  | `control_charts.md`    |
| Continuous, large subgroups (>10)          | X-bar S                  | `control_charts.md`    |
| Defectives, fixed sample size              | NP                       | `control_charts.md`    |

Also in Control: control plan (non-code), Nelson / Western Electric rules
(optional extension of control charts — see `control_charts.md`), periodic
capability re-scoring.

## Cross-cutting traps

A few reminders that apply across phases:

- **Check stability before capability.** Cp/Cpk on an unstable process is
  misleading. Run a control chart first, fix assignable causes, then score
  capability. A large Cpk-vs-Ppk gap is a stability red flag.
- **Check normality before any parametric test.** `shapiro.test()` plus a
  Q-Q plot. On small samples the parametric tests are forgiving; on
  capability indices they are not.
- **Don't pick one-sided tests to lower the p-value.** One-sided is for
  when the direction is declared in advance on theoretical grounds.
- **Correlation is not causation.** Before recommending a change based on
  regression, confirm with a before/after designed test.
- **Subgroup-size constants matter.** A2, D3, D4, d2, A3, B3, B4, c4 vary
  with n. `control_charts.md` has the table.

## What this skill does NOT cover

- **MSA / Gage R&R** — recommend `SixSigma::ss.rr()` or a custom `aov()` build.
- **Design of Experiments (DOE)** — recommend `FrF2`, `AlgDesign`, `rsm`.
- **Project-management artifacts** (charter, SIPOC, fishbone, FMEA,
  value-stream map) — diagrams/spreadsheets, not R code.
- **Cost/benefit modeling** — out of scope; a spreadsheet is the right tool.

If a request falls in one of these, say so explicitly and point the user
at the right tool — don't fake it with adjacent statistical output.
